1. ЧТО ЭТО ЗА ПРОЕКТ
================================================================

Производственный веб-инструмент для табачной линии SMD Cell2
(участок Cell2 разделён на 2 блока: LST 1 и LST 2).

Пользователи:
- Операторы — проходят чек-лист при смене сорта и контроль потерь.
- Технологи — управляют стандартами (OPL), настройками,
  историей, аналитикой.

Типы переходов при смене сорта (COCL):
- Minor (35 мин) — меняется табак и/или материалы.
  Бренд может не меняться (A → A).
- Intermediate (67 мин) — смена бренда + до 3 узлов.
  Бренд A → A запрещён.
- Major (90 мин) — смена бренда + более 3 узлов.
  Бренд A → A запрещён.

Дополнительный инструмент — TOP LOSSES:
Контроль стандартов, связанных с потерями, дефектами и выбросами
(TOP Losses). Оператор выбирает потерю (или несколько) — получает
список стандартов, которые её контролируют. Проверяет — получает
резюме «какие потери под контролем, какие нет».

Технологии: чистый HTML + CSS + JS без фреймворков.
Работает через file:// (двойной клик по index.html),
без сервера. ExcelJS подключён локально в js/exceljs.min.js.

ВАЖНО ПРО ФОТО:
Фотографии хранятся в папке photos/ рядом с index.html.
Пока нет сервера, каждый пользователь должен иметь свою
копию папки photos/. Планируется переезд на сервер —
тогда появится API для фото.

Структура папки photos:
    photos/<line>/<Maker|Packer>/<filename>
Примеры:
    photos/SD08/Maker/max-1.jpg
    photos/SD08/Packer/screenshot-1.png

В стандарте хранится ТОЛЬКО имя файла (например max-1.jpg).
Полный путь собирается автоматически через getPhotoPath().

3. УЧАСТОК И БЛОКИ
================================================================

Участок SMD Cell2 разделён на 2 блока:
- Cell2 (LST 1) — линии: SD06, SD12, SD27, SD31
- Cell2 (LST 2) — линии: SD01, SD03, SD08, SD25

Блоки редактируемые — в Настройках → «Блоки линий».
Каждая линия может быть только в одном блоке.

Машины для линий — свой список для каждой линии.
Задаётся в Настройках → «Машины для линий».
Пример: SD01: ['SE', 'M1', 'MAX'], SD03: ['SE', 'MAX'].

Машина в форме стандарта выбирается из выпадающего списка.
Кнопка «+» — быстрое добавление в справочник линии.

Двусторонняя синхронизация:
- Переименование машины в Настройках → обновляет во всех
  стандартах линии.
- Удаление машины → предупреждение о стандартах.
- Импорт Excel → автодобавление машин в справочник.

9. ВКЛАДКА TOP LOSSES (tab-toploss) — НОВОЕ
================================================================

Назначение: контроль стандартов по конкретным потерям.
Отдельное событие, не связанное со сменой сорта.

ЭКРАН 1 — выбор потерь:
- Верхние поля: Смена, Оператор, Линия (как в COCL).
- Список категорий с потерями (аккордеон или плитки).
- У каждой потери — чек-бокс + счётчик стандартов.
- Кнопка «Сформировать чек-лист» внизу.
- Множественный выбор: можно отметить 2–3 потери,
  получив объединённый список уникальных стандартов.

ЭКРАН 2 — чек-лист:
- Заголовок: список выбранных потерь.
- Стандарты в формате как в COCL (ОК/Не ОК / ввод / допуск).
- У каждого — пометка «Относится к: Обрыв штранга · Затор MAX».
- Кнопки «Сохранить» / «Отменить».

ЭКРАН 3 — резюме (Вариант B, без модалки):
После сохранения чек-лист заменяется экраном с итогом:

┌───────────────────────────────────────────────────┐
│  TOP LOSSES                                       │
├───────────────────────────────────────────────────┤
│  ✅ Проверка сохранена                            │
│                                                   │
│  Смена: B · Оператор: Иванов И.И. · 28.09 14:23   │
│                                                   │
│  Проверено стандартов: 12                         │
│  Отклонений: 2                                    │
│                                                   │
│  Потери под контролем:                            │
│   🟢 Обрыв штранга          8 / 8 OK              │
│   🟢 Затор на MAX           3 / 3 OK              │
│                                                   │
│  Требуют внимания:                                │
│   🔴 Замятие сигарет        1 / 3 не в норме      │
│      → OPL-4.2.1 — Не ОК                          │
│                                                   │
│  [← К списку потерь] [Проверить ещё потерю]      │
└───────────────────────────────────────────────────┘

Логика резюме:
- «Потери под контролем» — если ВСЕ стандарты этой потери дали ОК.
- «Требуют внимания» — если ХОТЯ БЫ ОДИН стандарт дал «Не ОК».
- Стандарт, привязанный к 2 потерям, попадает в обе группы.
- Кнопки:
  * «К списку потерь» — очищает экран, показывает выбор снова.
  * «Проверить ещё потерю» — то же, но с сохранением
    оператора/смены/линии для следующей проверки.

СОХРАНЕНИЕ В ИСТОРИЮ:
Одна проверка = одна запись:
{
  id: uid(),
  timestamp: ISO,
  mode: 'toploss',                  // ← отличает от 'changeover'
  operator, shift, line,
  topLosses: ['loss_strand', 'loss_max_jam'],
  items: [                          // как в COCL
    { standardId, oplNumber, machine, node, nodePart, title,
      controlType, norm, answer, status, comment }
  ]
}

События COCL и Top Losses — РАЗДЕЛЬНЫЕ, не смешиваются.

12. ВКЛАДКА ДАШБОРД (tab-dashboard)
================================================================

Состав (все виджеты на CSS + SVG, без библиотек):

ВЕРХНИЙ РЯД — 4 счётчика:
1. Стандарты (активные / всего).
2. Проверок сегодня.
3. Проверок за неделю.
4. Отклонений за 7 дней.

СРЕДНИЙ РЯД (2 колонки):
- Слева: «Последние 5 проверок».
- Справа: «Топ-5 проблемных стандартов (30 дней)».

НИЖНИЙ РЯД (2 колонки):
- Слева: «Отклонения по линиям (7 дней)» — двухцветный бар
  (зелёный = ОК, красный = fail). Сортировка по % (худшие сверху).
- Справа: «Топ операторов по отклонениям (30 дней)» — вариант В
  (абсолютное число + % + N из M). Сортировка по %.

ТРЕТИЙ РЯД (2 колонки):
- Слева: «Проверки по дням (7 дней)» — двухцветные столбики.
  * Высота = общее число проверок.
  * Верх — красный (проверки с отклонениями).
  * Низ — зелёный (проверки без отклонений).
  * Tooltip: «24.09: 8 проверок, из них 3 с отклонениями».
- Справа: «Типы переходов (30 дней)» — круговая (conic-gradient).

ЧЕТВЁРТЫЙ РЯД (2 колонки):
- Слева: «Отклонения по машинам (30 дней)» — двухцветный бар.
  Сортировка по абсолютному числу отклонений.
- Справа: «Динамика отклонений по неделям» — 4 ISO-недели
  (W39, W38, W37, W36), двухцветный бар, пустые недели
  пропускаются. Tooltip показывает диапазон дат.

ВНИЗУ:
- «Требует внимания» — умная карточка.
- «Быстрые действия» — 3 кнопки.

«ТРЕБУЕТ ВНИМАНИЯ» — агрегирует:
1. Битые ссылки на фото (из cl_photos_broken_count).
2. Стандарты без фото (активные с 0 фото).
3. Стандарты без проверок за 30 дней.
4. Операторы без активности > 7 дней.
5. Деактивированные стандарты с комментарием.
Если проблем нет — зелёное «Всё в порядке».

ВАЖНО: цветовая логика дашборда.
- Циан — активное, действия.
- Зелёный — ОК.
- Красный — отклонения.
- Фиолетовый — второстепенные категории (операторы).
- Амбер — интерфейсное.

Планируемое расширение дашборда (этап 6 Top Losses):
- Счётчик «Проверок потерь за неделю».
- Виджет «Топ-5 потерь по отклонениям (30 дней)».
- В «Требует внимания» — новые пункты (потери без проверок,
  стандарты без связи с потерями).
- Лист «Потери» в XLSX-отчёте.

13. ВКЛАДКА НАСТРОЙКИ (tab-settings)
================================================================

Порядок карточек:
