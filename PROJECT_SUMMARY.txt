1. ЧТО ЭТО ЗА ПРОЕКТ
================================================================

Производственный веб-инструмент для табачной линии SMD Cell2
(участок Cell2 разделён на 2 блока: LST 1 и LST 2).

Пользователи:
- Операторы — проходят чек-лист при смене сорта и контроль потерь.
- Технологи — управляют стандартами (OPL), настройками,
  историей, аналитикой.

Типы переходов при смене сорта (COCL):
- Minor (35 мин) — меняется табак и/или материалы.
  Бренд может не меняться (A → A).
- Intermediate (67 мин) — смена бренда + до 3 узлов.
  Бренд A → A запрещён.
- Major (90 мин) — смена бренда + более 3 узлов.
  Бренд A → A запрещён.

Дополнительный инструмент — TOP LOSSES:
Контроль стандартов, связанных с потерями, дефектами и выбросами.
Оператор открывает вкладку, выбирает потерю (или несколько) —
получает список стандартов, которые её контролируют.
В отличие от COCL, здесь проверка ОПЦИОНАЛЬНА: можно просто
изучить стандарты или отметить ОК / Не ОК для сохранения результата.

Технологии: чистый HTML + CSS + JS без фреймворков.
Работает через file:// (двойной клик по index.html),
без сервера. ExcelJS подключён локально в js/exceljs.min.js.

ВАЖНО ПРО ФОТО:
Фотографии хранятся в папке photos/ рядом с index.html.
Пока нет сервера, каждый пользователь должен иметь свою
копию папки photos/. Планируется переезд на сервер —
тогда появится API для фото.

Структура папки photos:
    photos/<line>/<Maker|Packer>/<filename>
Примеры:
    photos/SD08/Maker/max-1.jpg
    photos/SD08/Packer/screenshot-1.png

В стандарте хранится ТОЛЬКО имя файла (например max-1.jpg).
Полный путь собирается автоматически через getPhotoPath().

3. УЧАСТОК И БЛОКИ
================================================================

Участок SMD Cell2 разделён на 2 блока:
- Cell2 (LST 1) — линии: SD06, SD12, SD27, SD31
- Cell2 (LST 2) — линии: SD01, SD03, SD08, SD25

Блоки редактируемые — в Настройках → «Блоки линий».
Каждая линия может быть только в одном блоке.

Машины для линий — свой список для каждой линии.
Задаётся в Настройках → «Машины для линий».
Пример: SD01: ['SE', 'M1', 'MAX'], SD03: ['SE', 'MAX'].

Машина в форме стандарта выбирается из выпадающего списка.
Кнопка «+» — быстрое добавление в справочник линии.

Двусторонняя синхронизация:
- Переименование машины в Настройках → обновляет во всех
  стандартах линии.
- Удаление машины → предупреждение о стандартах.
- Импорт Excel → автодобавление машин в справочник.

ВАЖНО ПРО УНИКАЛЬНОСТЬ OPL:
OPL № уникален в пределах ЛИНИИ + МАШИНЫ. То есть:
- На линии SD01 можно создать OPL-1.1.1 [SE] и OPL-1.1.1 [MAX] —
  это РАЗНЫЕ стандарты, оба допустимы.
- На одной и той же машине одной линии два OPL-1.1.1 запрещены.
- На разных линиях с одинаковыми машинами OPL не пересекаются.

Это реализовано в:
- Валидации при сохранении формы стандарта (стандарт не создаётся,
  если есть дубликат по line+machine+oplNumber).
- Импорте Excel (ключ = line|machine|oplNumber).
- Сортировке в редакторе (при клике на «№ OPL» — сначала по
  машине, потом по OPL).
- Во всех отчётах и аналитике: OPL отображается как
  «OPL-1.1.1 [SE]» — с указанием машины.

9. ВКЛАДКА TOP LOSSES (tab-toploss) — РЕАЛИЗОВАНО
================================================================

Назначение: помощник проверки стандартов по конкретным потерям.
Проверка ОПЦИОНАЛЬНА — оператор может просто изучить стандарты
или отметить ОК / Не ОК и сохранить результат.

ЭКРАН 1 — выбор потерь:
- Верхние поля: Оператор (автокомплит), Линия. Смены НЕТ.
- Список категорий с потерями (аккордеон).
- У каждой потери — чек-бокс + счётчик стандартов на линии.
- Кнопка «Показать стандарты» внизу (sticky).
- Множественный выбор: можно отметить 2–3 потери,
  получив объединённый список уникальных стандартов.

Логика счётчиков на экране 1:
- Линия не выбрана → считает по всей базе.
- Линия выбрана → только по этой линии.
- У отмеченной потери счётчик становится циановым.
- Если у потери 0 стандартов → приглушённый амбер.

ЭКРАН 2 — список стандартов с опциональной оценкой:
- Шапка:
  * Заголовок «🎯 TOP Losses» с иконкой цели.
  * Строка «Потери:» + крупные циановые чипы выбранных потерь.
    Если потерь > 3 — первые 3 + кнопка «+N» (при клике — alert
    со всеми потерями).
  * Счётчик: «Показано N стандартов по M потерям».
  * Инфо-плашка с пояснением: «Это помощник проверки…».
- Список стандартов. У каждого пункта:
  * Мета (Часть · Машина · OPL · Узел).
  * Название.
  * Строка «Относится к: …» (список потерь, которые контролирует).
  * Строка действий: иконка глаза + кнопка «Отметить».
  * **Блок ответа СВЁРНУТ по умолчанию**.
- Клик «Отметить» → блок ответа РАСКРЫВАЕТСЯ:
  * Радио ОК / Не ОК (для ok_not_ok).
  * Поле значения (для value_input).
  * Поле значения + радио «В допуске / Не в допуске»
    (для tolerance).
  * Иконка комментария.
- Кнопка «Отметить» меняется на «Свернуть».
- Рядом с «Свернуть» появляется бейдж ответа:
  * «✓ ОК» (зелёный).
  * «✕ Не ОК» (красный).
  * «✓ 42» (зелёный, для value).
- Футер (sticky):
  * «← К выбору потерь».
  * Прогресс-бар появляется, когда есть хотя бы один ответ:
    «Отмечено: N / M · не проверено: K».
  * Кнопка «Зафиксировать результат» — НЕАКТИВНА, пока нет
    ни одного ответа. При ≥1 ответе — активируется.
- Сохранить можно в ЛЮБОЙ момент — необязательно заполнять все.
  Не отмеченные стандарты получают статус UNCHECKED
  («Не проверено»).

ЭКРАН 3 — визуальное резюме (после сохранения):
- Верхняя карточка «✓ Проверка сохранена» с мета:
  Оператор · Линия · Дата. Смены НЕТ.
- «Щит контроля» — круговая диаграмма с % ОК.
  * Зелёное кольцо, если всё ОК.
  * Красное/частичное, если есть FAIL.
  * Процент считается от ПРОВЕРЕННЫХ (ОК + Не ОК), а не от всех.
- Подпись: «Проверено: N из M · вне нормы: K · не проверено: J».
- Если есть FAIL — амберная подсказка:
  «⚠ Есть отклонения. Зафиксируйте их в Journal Machines.»
- Чипы-медальоны стандартов:
  * Зелёные (ОК), красные (Не ОК), серые (не проверено).
- Плитки потерь: по одной на каждую. С разбивкой:
  «N OK · M Не ОК · K не проверено».
- Кнопки внизу: «← К списку потерь» / «Проверить ещё потерю».

СОХРАНЕНИЕ В ИСТОРИЮ:
Одна проверка = одна запись с mode: 'toploss':
{
  id: uid(),
  timestamp: ISO,
  mode: 'toploss',
  operator,
  line,
  topLosses: ['loss_strand', 'loss_max_jam'],
  items: [
    { standardId, oplNumber, machine, node, nodePart, title,
      controlType, norm, answer, status, comment }
  ]
}

Статусы:
- 'OK' — отмечено «ОК».
- 'FAIL' — отмечено «Не ОК».
- 'UNCHECKED' — стандарт в списке, но оператор не отметил.

События COCL и Top Losses — РАЗДЕЛЬНЫЕ, не смешиваются.

================================================================
11. ВКЛАДКА ИСТОРИЯ (tab-history) — РЕАЛИЗОВАНО
================================================================

Фильтры:
- Период: всё / неделя / месяц / произвольный.
- Линия.
- Тип перехода: все / Minor / Intermediate / Major.
- Тип проверки: все / COCL / Top Losses.

Таблица записей:
- Колонка «Режим» — бейдж COCL (циан) или TOP (амбер).
- Колонка «Контекст»:
  * Для COCL: тип перехода + бренды.
  * Для TOP Losses: чипы потерь через «·».
- Колонка «Пунктов» — сколько всего.
- Колонка «Не ОК» — число FAIL.
- Колонка «Не проверено» — число UNCHECKED.
  * Для COCL — прочерк «—».
  * Для TOP Losses — амберный бейдж, если > 0.

ПАГИНАЦИЯ (как в редакторе стандартов):
- 10 записей на страницу по умолчанию.
- Выбор размера: 10 / 20 / 50.
- Навигация ← / → + номера страниц (5 вокруг текущей).
- Счётчик: «Показано X–Y из Z».
- Отдельные переменные historyPage / historyPageSize
  (не конфликтуют с пагинацией редактора).
- Сброс на 1-ю страницу при смене любого фильтра.

- Для TOP Losses: блок «Проверенные потери» (чипы).
- Итог: N пунктов, N ОК, N Не ОК.

Таблица пунктов (в модалке):
- Колонки: № · OPL · Машина · Узел · Название · Норма · Ответ · Комментарий.
- Колонка «Ответ» — БЕЗ дублирования:
  * ok_not_ok → только бейдж «ОК» (зелёный) / «Не ОК» (красный).
  * value_input → бейдж «ОК» + значение отдельной строкой.
  * tolerance → бейдж «В допуске / Не в допуске» + значение.

- Подсветка строк:
  * Зелёный фон — ОК.
  * Красный фон — Не ОК.
  * Амберный фон — Не проверено.

17. ЕДИНЫЙ TRANSITION ПРИ СМЕНЕ ТЕМЫ
================================================================

Реализовано через ОДНО правило в css/base.css:

  *,
  *::before,
  *::after {
    transition:
      background-color 0.35s ease,
      background 0.35s ease,
      color 0.35s ease,
      border-color 0.35s ease,
      fill 0.35s ease,
      stroke 0.35s ease,
      box-shadow 0.35s ease,
      width 0.35s ease,
      height 0.35s ease,
      transform 0.15s ease,   /* ← для hover */
      opacity 0.15s ease;     /* ← для hover */
  }

Логика:
- Все ЦВЕТА, ФОН, ГРАНИЦЫ, ТЕНИ, размеры — 0.35s ease,
  единообразно при смене темы.
- transform и opacity — 0.15s ease, для мгновенного hover-отклика.

ПРАВИЛА:
- НИ В ОДНОМ другом CSS-файле не должно быть своего transition:
  (ни в layout.css, ни в components.css, ни в style.css).
- Любое вхождение `transition:` кроме base.css — удалять.
- Единственный `animation:` (для появления модалок/тостов) —
  оставлен.

небольшая задержка — из-за количества DOM-элементов.
