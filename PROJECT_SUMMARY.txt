1. ЧТО ЭТО ЗА ПРОЕКТ
================================================================

Производственный веб-инструмент для табачной линии SMD Cell2
(участок Cell2 разделён на 2 блока: LST 1 и LST 2).

Пользователи:
- Операторы — проходят чек-лист при смене сорта, контроль потерь
  и контроль электронных параметров CL.
- Технологи — управляют стандартами (OPL), настройками,
  историей, аналитикой.

ТРИ РЕЖИМА ПРОВЕРКИ:
1. COCL — смена сорта (Minor / Intermediate / Major).
2. TOP Losses — контроль стандартов, связанных с потерями,
   дефектами и выбросами. Проверка ОПЦИОНАЛЬНА.
3. CL Electronic — проверка электронных параметров CL
   на старых машинах, где нет автоподтягивания данных.

Технологии: чистый HTML + CSS + JS без фреймворков.
Работает через file:// (двойной клик по index.html),
без сервера. ExcelJS подключён локально в js/exceljs.min.js.

ВАЖНО ПРО ФОТО:
Фотографии хранятся в папке photos/ рядом с index.html.
Пока нет сервера, каждый пользователь должен иметь свою
копию папки photos/. Планируется переезд на сервер — тогда
появится API для фото.

Структура папки photos:
    photos/<line>/<Maker|Packer>/<filename>

В стандарте хранится ТОЛЬКО имя файла (например max-1.jpg).
Полный путь собирается автоматически через getPhotoPath().

3. УЧАСТОК И БЛОКИ
================================================================

Участок SMD Cell2 разделён на 2 блока:
- Cell2 (LST 1) — линии: SD06, SD12, SD27, SD31

Задаётся в Настройках → «Машины для линий».

ВАЖНО ПРО УНИКАЛЬНОСТЬ OPL:
OPL № уникален в пределах ЛИНИИ + МАШИНЫ.
- На линии SD01 можно создать OPL-1.1.1 [SE] и OPL-1.1.1 [MAX] —
  это РАЗНЫЕ стандарты, оба допустимы.
- На одной и той же машине одной линии два OPL-1.1.1 запрещены.

5. СТРУКТУРА ЭЛЕКТРОННОГО ПАРАМЕТРА (CL ELECTRONIC)
================================================================

electronicParam = {
  id: '', active: true,
  line: '', machine: '', paramName: '',
  work: 'Run',                   // 'Run' | 'Stop'
  timeFrom: '09:10', timeTo: '10:00',
  controlType: 'value_input',    // 'value_input' | 'ok_not_ok'
  normText: '',                  // для ok_not_ok
  valuesByBrand: [               // для value_input
    { brand: 'A', target: 10, tolerance: 5 }
  ],
  frequency: {
    type: 'daily',               // 'daily' | 'weekly' | 'once'
    shifts: ['day', 'night'],    // 'day' 09:00–21:00, 'night' 21:00–09:00
    daysOfWeek: [],              // для weekly
    dates: []                    // для once ('YYYY-MM-DD')
  },
  author: '', createdAt: null, updatedAt: null
}

Ключ уникальности: line + machine + paramName.

ВАЖНО ПРО ПЕРИОДИЧНОСТЬ:
- 'daily' — каждый день (в смены 'day' и/или 'night').
- 'weekly' — по дням недели (0=Вс..6=Сб), в смены 'day'/'night'.
- 'once' — конкретные даты.
- 'rotation' — БОЛЬШЕ НЕ ИСПОЛЬЗУЕТСЯ.

СМЕНЫ CL ELECTRONIC:
Две 12-часовые смены в сутки:
- День 09:00–21:00
- Ночь 21:00–09:00 (след. дня, датируется датой начала)

Буквы A/B/C/D — БРИГАДЫ, а не смены.

ГРАФИК СМЕН (актуальный на 01.10.2026):
Проверенная последовательность смен — 16-дневный цикл,
чередование день/ночь:

| День | Дневная | Ночная |
|------|---------|--------|
| 1    | B       | A      |
| 2    | D       | C      |
| 3    | D       | C      |
| 4    | A       | B      |
| 5    | A       | B      |
| 6    | C       | D      |
| 7    | C       | D      |
| 8    | B       | A      |
| 9    | B       | A      |
| 10   | D       | C      |
| 11   | D       | C      |
| 12   | A       | B      |
| 13   | A       | B      |
| 14   | C       | D      |
| 15   | C       | D      |
| 16   | B       | A      |

Затем цикл повторяется с 17.10.2026 (день 1 = B / A).
Реально это 8-дневный цикл, повторённый дважды.

Структура localStorage cl_electronic_shiftcfg_v1:
{
  dayCycle:   ['B','D','D','A','A','C','C','B'],
  nightCycle: ['A','C','C','B','B','D','D','A'],
  startDate:  '2026-10-01'
}

ВАЖНО: при смене DEFAULT_ELECTRONIC_SHIFT_CFG в app.js —
обязательно чистить localStorage:
  localStorage.removeItem('cl_electronic_shiftcfg_v1');
  location.reload();
Иначе getElectronicShiftConfig() вернёт старый конфиг из LS.

ВКЛАДКА «CL ELECTRONIC» — В РАБОТЕ:

Редактор (электронный режим):
- Переключатель режима (Механический / Электронный).
- Список линий → список машин → список параметров.
- Форма параметра: Line, Machine, ParamName, Work (Run/Stop),
  Time (From/To), ControlType (value_input / ok_not_ok),
  NormText, ValuesByBrand, Frequency (daily / weekly / once).
- Модалка «Расписание брендов» с двумя режимами (по периодам / по дням).

Вкладка проверки CL Electronic:
- Экран 1: оператор, линия, контекст (дата, смена, бренд).
- Бренд подтягивается из расписания, есть override.
- Чек-лист параметров на сегодня:
  * Мета: время, машина, Run/Stop.
  * Норма: target ± tolerance → [min, max] или normText.
  * Поле значения с авто-проверкой в допуске.
  * Радио ОК / Не ОК.
  * Иконка комментария.
- Кнопки «Обновить» / «Зафиксировать результат».
- Сохранение в Историю с mode: 'electronic'.
- Экран 2 — резюме:
  * «Щит контроля» с кольцом %ОК.
  * Чипы стандартов.
  * Кнопки «← К проверке» / «Новая проверка».
  * Плашка «Journal Machines» (при наличии FAIL).
  * Матрица недели внутри резюме (секция «Неделя целиком»).

Матрица недели:
- За текущую ISO-неделю (Пн..Вс), а не 7 дней вперёд.
- Колонки: Машина | Параметр | Время | Run/Stop | Норма |
  7 × (День / Ночь).
- Машина — заглавным, жирным, синим (--blue-mid).
- Run — зелёный чип, Stop — оранжевый.
- Легенда под таблицей (Запланировано / ОК / Не ОК / Не проверено).
- Сегодняшняя смена — обводка.

История — CL Electronic:
- Фильтр по режиму, бейдж E-PARAM (фиолетовый).
- В модалке записи — бренд (факт + план).
