1. ЧТО ЭТО ЗА ПРОЕКТ
================================================================

Производственный веб-инструмент для табачной линии SMD Cell2
(участок Cell2 разделён на 2 блока: LST 1 и LST 2).

Пользователи:
- Операторы — проходят:
  * COCL (смена сорта / CL в ТО / CL в Конвертацию),
  * TOP Losses (потери, дефекты, выбросы),
  * Чек-лист CL — регулярные проверки
    механических стандартов и электронных параметров.
- Технологи — управляют стандартами, расписанием CL,
  настройками, историей, аналитикой.

Технологии: чистый HTML + CSS + JS без фреймворков.
Работает через file:// (двойной клик по index.html),
без сервера. ExcelJS подключён локально в js/exceljs.min.js.

ПРИНЦИПИАЛЬНОЕ РЕШЕНИЕ:
SPA (Single Page Application) — один index.html + вкладки
через div.tab. Никаких отдельных страниц. Формы стандарта и
E-Param — полные страницы внутри SPA (#tab-standard-view,
#tab-eparam-edit); модалки — для коротких окон (выбор,
подтверждение). Свой роутер (router.js) на hash.

ВАЖНО ПРО ФОТО:
Фотографии хранятся в папке photos/ рядом с index.html.
Пока нет сервера, каждый пользователь должен иметь свою
копию папки photos/. Планируется переезд на сервер — тогда
появится API для фото.

Структура папки photos:
    photos/<line>/<Maker|Packer>/<filename>

В стандарте хранится ТОЛЬКО имя файла (например max-1.jpg).
Полный путь собирается автоматически через getPhotoPath().

ТИПЫ КОНТРОЛЯ (ПЕРЕРАБОТАНО — 3 канонических типа):
- fixed     — «Фиксированный». Точки ОПЦИОНАЛЬНЫ.
              С точками → оператор вводит точное значение (без
              допуска). Без точек → «ОК / Не ОК».
- variable  — «Вариабельный». Всегда точки. Формат «92 ± 5»,
              «92+-5» (target ± tolerance).
- interval  — «Контролируемый интервал». Формат «5 до 8»,
              «5.5 - 8.5», «-65 до -55», «5.5…8.5».

Миграция legacy-типов (migrateControlType в js/data/standards.js):
- ok_not_ok    → fixed
- range_input  → interval
- tolerance    → variable
- value_input  → variable (если точки с допуском) или fixed
                 (жёсткое значение без допуска).
Миграция выполняется автоматически при чтении (нормализация)
и при сохранении; старые данные не ломаются.

Единицы измерения — часть строки значения: «-65 kPa (±10 kPa)».

ПАРСИНГ НОРМЫ (parseNorm) — без изменений:
- variable:  92 ± 5   → { min: 87, max: 97 }
- interval:  5 до 8   → { min: 5, max: 8 }
- Одиночное число: 0  → { min: 0, max: 0 } (точное совпадение)
- Пусто/не распознано → null

ЛОГИКА ФИЛЬТРАЦИИ У ОПЕРАТОРА (COCL):
- ChangeOver:
  * Стандарт виден в «Смене сорта» только если набор точек
    целевого бренда ОТЛИЧАЕТСЯ от набора точек исходного бренда
    (сравнение brandBlocksDiffer по числу и значениям точек),
    ЛИБО у стандарта forceInChangeOver === true.
  * Если точки всех брендов совпадают — стандарт НЕ показывается.
  * Показывается набор точек целевого бренда (fallback на «Все»).
  * + проверка триггеров (пользовательских).
- CL_TO / CL_Conversion:
  * Все стандарты с соответствующим appliesTo.
  * Триггеры НЕ проверяются.
  * Бренды НЕ выбираются.

ОТОБРАЖЕНИЕ У ОПЕРАТОРА (чек-лист COCL):
- Аккордеон (cocl-acc-item).
- Иконка 💬 — комментарий.
- Иконка 👁 — просмотр стандарта.
- Сетка точек 3×N с авто-подсветкой (✓/✕).
- Экран резюме после сохранения.

В ФОРМЕ E-PARAM:
- Поля: Линия (readonly) · Машина · Часть линии (Maker/Packer,
  только SMD) · Описание параметра · Работа (Run/Stop) ·
  Тип контроля · Текст нормы / Значения по брендам ·
  Триггеры Change Over · Применяемость (ChangeOver / CL_TO /
  CL_Conversion).
- НЕТ секции «Периодичность» — она настраивается в «Расписании CL».
- НЕТ полей «Время проверки».
- Тип контроля: fixed (текст нормы) / variable+interval
  (таблица значений по брендам target±tolerance).

ПЕРИОДИЧНОСТЬ:
- 'weekly' — по дням недели (основной режим).
- 'daily' — каждый день.
- 'once' — конкретные даты.
- 'rotation' — БОЛЬШЕ НЕ ИСПОЛЬЗУЕТСЯ.

СМЕНЫ:
Две 12-часовые смены: день 09:00–21:00, ночь 21:00–09:00.
Буквы A/B/C/D — БРИГАДЫ, а не смены.

ГРАФИК СМЕН (актуальный на 01.10.2026):
| День | Дневная | Ночная |
|------|---------|--------|
| 1    | B       | A      |
| 2    | D       | C      |
| 3    | D       | C      |
| 4    | A       | B      |
| 5    | A       | B      |
| 6    | C       | D      |
| 7    | C       | D      |
| 8    | B       | A      |
Затем цикл повторяется с 9-го дня.

8. ЕДИНЫЙ ЧЕК-ЛИСТ CL (вкладка #electronic)
================================================================

КОНЦЕПЦИЯ:
Вкладка «CL Electronic» переделана в «Чек-лист CL» —
единый чек-лист с переключателем между механикой и
электроникой.

ВХОД:
- Автоматически открывается модалка выбора линии
  (#linePickerModal).
- ФИО оператора НЕ выбирается — заглушка '—'.

ПЕРЕКЛЮЧАТЕЛИ:
- Механические / Электронные.
- Maker / Packer (скрыт для «Электронных»).

МАТРИЦА:
Инфо-колонки: № · OPL № · Машина · Узел · Название CL ·
Время · Работа (Run/Stop) · Норма / точки.
+ 14 смен: 7 дней × 2 смены.

ШАПКА СМЕН:
- Верхний ряд: Пн 12.10, Вт 13.10, ...
- Нижний ряд: «День · A», «Ночь · B», «День · A», ... —
  буква бригады из getShiftsForDate(dateStr).

КОЛОНКА «ВРЕМЯ»:
- Показывает чипы из frequency.timeWindows.
- Дневные окна (from >= '09' и < '21') — циановые.
- Ночные окна (from >= '21' или < '09') — фиолетовые.
- Пусто → «—».

КОЛОНКА «НОРМА / ТОЧКИ»:
- Тип fixed (без точек) → оранжевая галочка (✓) — отличается
  от RUN.
- Тип fixed (с точками) → точное значение (без допуска).
- Тип variable, 1 точка → «target ± tolerance».
- Тип variable, > 1 точки → «N точки».
- Тип interval, 1 точка → «min…max».
- Тип interval, > 1 точки → «N точки».
- Выровнена по центру.

ЛОГИКА ОТОБРАЖЕНИЯ:
- Показываются только стандарты/параметры с inSchedule=true.
- В ячейке:
  * `na` (—) — не запланировано (нет в schedule).
  * `due` (пусто) — запланировано, ещё не проверено.
  * `ok` (✓) — проверено ОК.
  * `fail` (✕) — проверено Не ОК.
  * `unchecked` (?) — проверено «не проверено».

РЕЖИМЫ:
- Кнопка «Начать проверку» — активирует режим проверки.
- Кнопка меняется на «Закончить проверку».
- Кликабельна ТОЛЬКО ячейка сегодняшнего дня и текущей смены:
  * ЛКМ → модалка быстрой проверки (#quickCheckModal).
  * Shift+ЛКМ → мгновенно ✓.
  * Alt+ЛКМ → мгновенно ✕.
- Прошлое/будущее — только просмотр.
- «Закончить проверку» сохраняет все draft в history.

КОНТЕКСТ-СТРОКА:
Дата · Смена (День/Ночь · бригада X) · Бренд (с override).

БРЕНД ДНЯ:
- Берётся из расписания брендов
  (getElectronicBrandForDate).
- Fallback: блок measurements с пустым brand.
- Override: кнопка «изменить бренд», сохраняется в brandReason.

ПРОСМОТР СТАНДАРТА:
- Кнопка «глаз» в строке (колонка «Название CL»).
- Клик по названию стандарта.
- Открывает #standardViewModal — как в TOP Losses.

ФУНКЦИИ:
- openClCheckTab() — открытие вкладки.
- renderClMatrix() — рендер матрицы.
- renderClRow() — рендер строки.
- bindClCells() — обработчики кликов.
- openClCheckModal(rowId, dateStr, shift) — модалка.
- saveQuickCheck() — сохранение в clState.quickDraft.
- startClCheck() / stopClCheck() — режим проверки.
- saveClDraftToHistory() — финальное сохранение.

МОДАЛКА БЫСТРОЙ ПРОВЕРКИ (#quickCheckModal):
- Универсальная: работает и для мех, и для электро.
- Различает по quickCheckState.isElec.
- Контекст: линия · машина, стандарт, узел, время, Run/Stop,
  дата/смена, бренд.
- Норма:
  * fixed (без точек или электро) → normText или controlDescription.
  * variable / interval (мех) → точки замера.
  * variable / interval (электро) → target ± tolerance для бренда.
- «Как проверять» — сворачиваемое описание контроля (только мех).
- Для fixed (ОК/Не ОК) — радио ОК / Не ОК.
- Для мех variable/interval/fixed-с-точками — поля по точкам
  (qc-point-input) с авто-подсветкой ✓/✕.
- Для электро variable/interval — одно числовое поле.
- Сохраняет статус по допуску (для электро считается по
  target±tolerance выбранного бренда).

9. РАСПИСАНИЕ CL (вкладка #schedule, аналитик)
================================================================

КОНЦЕПЦИЯ:
Технолог формирует список стандартов/параметров, которые
будут регулярно проверяться оператором, и проставляет

ВХОД:
- Автоматически открывается модалка выбора линии.

ПЕРЕКЛЮЧАТЕЛИ:
- Механические / Электронные.
- Maker / Packer (для механики).

ТУЛБАР (над матрицей):
- Фильтр «Машина» (выпадающий список).
- Поиск по OPL / названию / узлу / машине.
- Справа — счётчики: Всего / С расписанием / Заполнено
  ячеек (из M×14).
- Легенда: День (циан), Ночь (фиолет).

МАТРИЦА:
Инфо-колонки: № · OPL № · Машина · Узел · Название ·
Время · Run/Stop · Расписание (счётчик «N из 14») ·
Действия (✕ убрать из расписания).
+ 14 смен: 7 дней × 2 смены.

ШАПКА СМЕН:
- Верхний ряд: Пн 12.10, ...
- Нижний ряд: «День · A», «Ночь · B», ... — буквы бригад.

КОЛОНКА «ВРЕМЯ»:
- Время считается само (сессия 15), вручную не задаётся: Run / Stop —
  первый час смены по отмеченным сменам недели (только день → 09:00–10:00,
  только ночь → 21:00–22:00, обе → оба окна); CIL — без окна, в колонке
  «по ситуации», просрочка только после конца смены.
- autoTimeWindows(work, schedule) в js/data/schedule.js; хранимые
  frequency.timeWindows не читаются, перезаписываются при сохранении.
- Цвет чипа: день (циан) / ночь (фиолет) — по часу `from`.

ЯЧЕЙКИ СМЕН:
- Клик → toggle пары {day, shift} в schedule.
- Циан — день, фиолетовый — ночь.
- Счётчик «N из 14» в колонке «Расписание» обновляется.

КНОПКИ В ШАПКЕ:
- «Добавить стандарты» (открывает модалку выбора).
- «Сохранить изменения».

НЕДЕЛИ И ВЕРСИИ ШАБЛОНА (сессия 6) — ПРОШЛОЕ НЕ МЕНЯЕТСЯ:
- У строки frequency.templates = [{ from, inSchedule, schedule,
  timeWindows, work }], from — понедельник недели, с которой
  действует версия. Для недели W берётся последняя версия с
  from <= W. Нет версий — действуют «исходные» поля (inSchedule,
  frequency.schedule/timeWindows, work); исходные поля всегда
  повторяют самую позднюю версию (их читают импорт/экспорт).
- Разовые правки недели — cl_schedule_weeks_v1
  { weekStart: { line: { removed, added, rows } } }.
- Неделя = getRowTemplateForWeek + разовые правки → getRowForWeek.
  Им пользуются и Расписание (getSchRowFreq, isSchRowMember), и
  Чек-лист (getClRowFreq, состав строк).
- Переключатель «Сохранить: С этой недели и далее | Только эта
  неделя». «Далее» на будущей неделе — версия с этой недели; на
  текущей — оставшиеся смены разовой правкой, версия со следующей
  недели (прошедшие дни не трогаются, жёлтых «?» не появляется).
  Перед заменой более поздних версий — подтверждение.
- Блокируются только закончившиеся смены (isShiftPast: текущую
  ещё можно отметить), прошедшая неделя — только просмотр.
- С пятницы по воскресенье вкладка открывается на следующей
  неделе; кнопки «Эта неделя / Следующая».
- «Текущая неделя» везде считается от даты текущей смены
  (getClWeekDays, getSchWeekStart): понедельник 00:00–09:00 —
  ещё ночь воскресенья.

УБРАНО:

ФУНКЦИИ:
