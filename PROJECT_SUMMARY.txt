1. ЧТО ЭТО ЗА ПРОЕКТ
================================================================

Производственный веб-инструмент для табачной линии SMD Cell2
(участок Cell2 разделён на 2 блока: LST 1 и LST 2).

Пользователи:
- Операторы — проходят чек-лист при смене сорта, контроль потерь
  и контроль электронных параметров CL.
- Технологи — управляют стандартами (OPL), настройками,
  историей, аналитикой.

ТРИ РЕЖИМА ПРОВЕРКИ:
1. COCL — смена сорта (ChangeOver / CL в ТО / CL в Конвертацию).
2. TOP Losses — контроль стандартов, связанных с потерями,
   дефектами и выбросами. Проверка ОПЦИОНАЛЬНА.
3. CL Electronic — проверка электронных параметров CL
   на старых машинах, где нет автоподтягивания данных.

Технологии: чистый HTML + CSS + JS без фреймворков.
Работает через file:// (двойной клик по index.html),
без сервера. ExcelJS подключён локально в js/exceljs.min.js.

ВАЖНО ПРО ФОТО:
Фотографии хранятся в папке photos/ рядом с index.html.
Пока нет сервера, каждый пользователь должен иметь свою
копию папки photos/. Планируется переезд на сервер — тогда
появится API для фото.

Структура папки photos:
    photos/<line>/<Maker|Packer>/<filename>

В стандарте хранится ТОЛЬКО имя файла (например max-1.jpg).
Полный путь собирается автоматически через getPhotoPath().

4. СТРУКТУРА СТАНДАРТА (OPL) — МЕХАНИЧЕСКИЙ
================================================================

standard = {
  id: '', active: true,
  number: '', oplNumber: '', machine: '',
  title: '', line: '', node: '', nodePart: '',
  controlType: '',               // ok_not_ok / value_input / range_input
  problemDescription: '', controlDescription: '',
  purpose: '', whyCreated: '',

  // Точки замера — блоки по брендам (НОВАЯ СТРУКТУРА):
  measurements: [
    {
      brand: '',           // '' = «Все бренды», иначе название бренда
      points: [
        { value: '92 ± 5' },      // значение/норма точки
        { value: '33 ± 3' },
        ...
      ]
    },
    {
      brand: 'Кент',
      points: [ ... ]
    }
  ],

  appliesTo: [],                 // ChangeOver / CL_TO / CL_Conversion
  triggers: [],                  // материалы / узлы (node:Название)
                                 // Работает ТОЛЬКО для ChangeOver
  topLosses: [],                 // ID потерь из cl_toplosses_v1
  photos: [],                    // имена файлов
  author: '', createdAt: null, updatedAt: null,
  deactivationComment: '', deactivationHistory: []
}

ТИПЫ КОНТРОЛЯ:
- ok_not_ok     — «ОК / Не ОК». БЕЗ точек замера (блок скрыт).
- value_input   — «Число ± допуск». Формат: «92 ± 5», «92+-5».
- range_input   — «Диапазон». Формат: «5 до 8», «5.5 - 8.5»,
                  «-65 до -55», «5.5…8.5».

Единицы измерения — часть строки значения: «-65 kPa (±10 kPa)».

ПАРСИНГ НОРМЫ (parseNorm):
- value_input:  92 ± 5  → { min: 87, max: 97 }
- range_input:  5 до 8  → { min: 5, max: 8 }
- Одиночное число: 0    → { min: 0, max: 0 } (точное совпадение)
- Пусто/не распознано → null

ЛОГИКА ФИЛЬТРАЦИИ У ОПЕРАТОРА (COCL):
- ChangeOver:
  * Стандарт виден ТОЛЬКО если у него есть блок точек для
    выбранного бренда «На бренд».
  * Показывается набор точек ЭТОГО бренда (без fallback на «Все»).
  * + проверка триггеров (если у стандарта есть triggers).
- CL_TO / CL_Conversion:
  * Показываются все стандарты с соответствующим appliesTo.
  * Триггеры НЕ проверяются.
  * Бренды НЕ выбираются.

УНИВЕРСАЛЬНОЕ ПРАВИЛО: у всех брендов в стандарте ОДИНАКОВОЕ
число точек. Добавили точку → у всех брендов. Удалили → у всех.

5. СТРУКТУРА ЭЛЕКТРОННОГО ПАРАМЕТРА (CL ELECTRONIC)
================================================================

electronicParam = {
  id: '', active: true,
  line: '', machine: '', paramName: '',
  work: 'Run',                   // 'Run' | 'Stop'
  timeFrom: '09:10', timeTo: '10:00',
  controlType: 'value_input',    // 'value_input' | 'ok_not_ok'
  normText: '',                  // для ok_not_ok
  valuesByBrand: [               // для value_input
    { brand: 'A', target: 10, tolerance: 5 }
  ],
  frequency: {
    type: 'daily',               // 'daily' | 'weekly' | 'once'
    shifts: ['day', 'night'],    // 'day' 09:00–21:00, 'night' 21:00–09:00
    daysOfWeek: [],              // для weekly (0=Вс, 1=Пн, ..., 6=Сб)
    dates: []                    // для once ('YYYY-MM-DD')
  },
  author: '', createdAt: null, updatedAt: null
}

Ключ уникальности: line + machine + paramName.

ВАЖНО ПРО ПЕРИОДИЧНОСТЬ:
- 'daily' — каждый день (в смены 'day' и/или 'night').
- 'weekly' — по дням недели (0=Вс..6=Сб), в смены 'day'/'night'.
- 'once' — конкретные даты.
- 'rotation' — БОЛЬШЕ НЕ ИСПОЛЬЗУЕТСЯ. Удалён из UI.
  Старые данные мигрируются в 'daily' с shifts: ['day','night'].

СМЕНЫ CL ELECTRONIC:
Две 12-часовые смены в сутки:
- День 09:00–21:00
- Ночь 21:00–09:00 (след. дня, датируется датой начала)

Буквы A/B/C/D — БРИГАДЫ, а не смены.

ГРАФИК СМЕН (актуальный на 01.10.2026):

| День | Дневная | Ночная |
|------|---------|--------|
| 1    | B       | A      |
| 2    | D       | C      |
| 3    | D       | C      |
| 4    | A       | B      |
| 5    | A       | B      |
| 6    | C       | D      |
| 7    | C       | D      |
| 8    | B       | A      |

Затем цикл повторяется с 9-го дня.
Это 8-дневный цикл, повторяющийся.

Структура localStorage cl_electronic_shiftcfg_v1:
{
  dayCycle:   ['B','D','D','A','A','C','C','B'],
  nightCycle: ['A','C','C','B','B','D','D','A'],
  startDate:  '2026-10-01'
}

ВАЖНО: при смене DEFAULT_ELECTRONIC_SHIFT_CFG в app.js —
обязательно чистить localStorage:
  localStorage.removeItem('cl_electronic_shiftcfg_v1');
  location.reload();
Иначе getElectronicShiftConfig() вернёт старый конфиг из LS.

9. СТЕК МОДАЛЬНЫХ ОКОН (универсальная система)
================================================================
Реализован через стек. Функции в app.js:

- const modalStack = [];
- openModal(modalOrId) — открывает, назначает z-index
  поверх стека, приостанавливает родительскую (класс
  .modal-suspended).
- closeModal(modalOrId) — закрывает, снимает .modal-suspended
  со всех, которые должны быть видны (в стеке), и скрывает
  те, что не в стеке.
- bindModalBackdropClose(modalId) — клик вне модалки закрывает.

CSS:
- .modal-overlay.modal-suspended {
    opacity: 0; visibility: hidden;
    pointer-events: none;
  }

Базовая z-переменная в base.css: --modal-z-base: 2000.

ПРАВИЛО: любые модалки открывать через openModal(),
закрывать через closeModal(). НЕ использовать
classList.add('active') / remove('active') напрямую в других
функциях для модалок.

Лайтбокс (#lightboxModal) — всегда с z-index: 9999, поверх любых.

РЕДАКТОР СТАНДАРТОВ — НОВАЯ СТРУКТУРА ТОЧЕК:

- Визуально — таблица с общей шапкой:

- Крестики у колонок (удаление у всех брендов) и рядом с брендом.
- Валидация при открытии формы — при `ok_not_ok` блок точек
  скрывается (`updateStandardPointsVisibility`).

РЕДАКТОР СТАНДАРТОВ — «ПРИМЕНЯТЬ К»:
- Перемещён под «Точки замера».
- Заменено на 3 чекбокса Change Over / CL в ТО / CL в Конвертацию.

РЕДАКТОР СТАНДАРТОВ — СВОРАЧИВАЕМЫЕ БЛОКИ:
- «Триггеры Change Over (опционально)» — циановая полоса слева.
- «Top Losses» — амберная полоса слева.
- По умолчанию свёрнуты, разворачиваются по клику.

РЕДАКТОР СТАНДАРТОВ — TOP LOSSES (НОВЫЙ ПОДХОД):
- Показ только выбранных потерь.
- Кнопка «+ Добавить потерю» → модалка с поиском.
- Счётчик «Применено: N» в шапке блока.
- Модалка `#topLossPickerModal` — группировка по категориям,
  чипы, поиск, счётчик «Выбрано: N».

ВКЛАДКА «ПРОВЕРКА COCL»:
- Форма оператора, смены, линии, части, типа.
- Новые типы: Change Over / CL в ТО / CL в Конвертацию.
- Для Change Over — выбор брендов «С бренда» / «На бренд».
- Для CL_TO / CL_Conversion — бренды скрыты.
- Валидация: оператор, смена, линия, часть, тип — обязательны
  до формирования чек-листа.
- Кнопка «Сформировать проверку» — верхняя часть формы
  скрывается, показывается чек-лист.
- Кнопка «← Изменить условия» — возврат к настройке.

ЧЕК-ЛИСТ COCL (АККОРДЕОН):
- Компактные строки, один раскрытый стандарт (авто-первый).
- Цветные полоски: амбер/циан/зелёный/красный (статус).
- Иконки: 💬 комментарий (амберный при наличии), 👁 глазик.
- Сетка точек 3×N с авто-подсветкой:
  * Ячейка `checklist-point-cell` — номер, норма, поле ввода.
  * Значок ✓/✕ слева от номера (при вводе значения).
  * Цвет фона и рамки ячейки: зелёный / красный.
- Прогресс: «Проверено X из Y · ОК: N · Не ОК: M».

ЭКРАН РЕЗЮМЕ COCL:
- «Щит контроля» с кольцом %ОК.
- Чипы стандартов (OK/FAIL/UNCHECKED).
- Кнопки «← К истории» / «Новая проверка».
- Плашка «Journal Machines» при отклонениях.

TOP LOSSES У ОПЕРАТОРА (АККОРДЕОН):
- Единый стиль с COCL.
- **Всегда ОК / Не ОК** (без ввода значения) — даже для
  value_input / range_input стандартов.
- Экраны: Выбор потерь → Чек-лист → Резюме.
- Авто-раскрытие первого непроверенного.
- Индикация: 💬, 👁, ✓/✕, %ОК.
- Экран резюме с «щитом контроля».

ИСТОРИЯ:
- Бейдж режима зависит от типа:
  * ChangeOver → CHANGE OVER (циан)
  * CL_TO → CL В ТО (фиолетовый)
  * CL_Conversion → CL В КОНВЕРТ. (изумрудный)
  * TOP Losses → TOP (амбер)
  * CL Electronic → E-PARAM (фиолетовый)
- Модалка просмотра записи: норма через `·`, ответ через `·`.
- Вспомогательные функции: `renderRecordNorm`, `renderRecordAnswer`.

    Описание контроля | Цель | Почему создан | Триггеры |
    Top Losses | Фото

    OPL № | Машина | Бренд | № точки | Значение

  * Читает «Точки» если есть — связывает по `OPL № + Машина`.
  * Машины, которых нет в списке — автодобавляются.
  * Триггеры/Top Losses — по названиям.
