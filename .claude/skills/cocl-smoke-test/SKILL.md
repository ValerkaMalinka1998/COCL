# Смоук-тест COCL

Приложение работает через `file://` без сервера, поэтому ошибки JS видны только
в консоли браузера. Пользователь раньше проверял их руками после каждой правки
(Ctrl+Shift+R → консоль). Этот скилл делает то же самое автоматически, чтобы до
пользователя не доходил код, который падает при открытии вкладки.

## Запуск

Из корня репозитория:

```bash
python3 .claude/skills/cocl-smoke-test/scripts/smoke_test.py --out <scratchpad>/smoke
```

На Windows (локальная машина) `python3` — заглушка Microsoft Store; запускать так:

```powershell
$env:PYTHONIOENCODING = "utf-8"
& "$env:LOCALAPPDATA\Programs\Python\Python312\python.exe" .claude/skills/cocl-smoke-test/scripts/smoke_test.py --out <scratchpad>/smoke
```

Полезные флаги:
- `--line SD01` — линия для Чек-листа / Редактора / Расписания (по умолчанию `SD12`:
  в тестовом бэкапе стандарты есть только на ней).
- `--no-seed` — пустой localStorage, проверка «первого запуска». Шаги, которым
  нужны данные (форма E-Param, экспорт стандартов), пропускаются как ожидаемые.
- `--backup файл.json` — свой бэкап вместо самого свежего `checklist_backup_*.json`.
- `--theme dark` — скриншоты в тёмной теме (по умолчанию светлая). После визуальных
  правок прогоняй обе темы.

Гоняй оба режима (с данными и `--no-seed`), если правка трогает инициализацию,
миграции или `STORAGE_KEYS`: ошибки на пустом хранилище — частый класс багов.

Код выхода 1 — есть ошибки JS или проваленный шаг. Отчёт `smoke-report.json` и
скриншоты всех вкладок/модалок лежат в `--out`.

## Как читать результат

- **errors** — `pageerror` и `console.error`. Любая такая ошибка = правка не готова.
  Поле `where` говорит, на какой вкладке/шаге она возникла.
- **warnings** — отсутствующие фото в `photos/` и предупреждения консоли. Фото
  ожидаемо отсутствуют (у каждого пользователя своя папка), это не баг.
- **FAIL шага** без ошибки JS обычно значит, что модалка не открылась или вкладка
  не стала активной — посмотри скриншот этого шага.

Когда что-то упало: найди причину, исправь, прогони тест ещё раз. Не сообщай
пользователю «готово», пока тест не зелёный, или явно скажи, что осталось красным
и почему.

## Скриншоты

После визуальных правок открой нужный `tab-*.png` / `modal-*.png` через Read и
посмотри глазами: тест ловит падения, но не кривую вёрстку.

## Чего тест не покрывает

Клики по ячейкам матрицы Чек-листа и Расписания, сохранение форм, импорт XLSX,
COCL-чек-лист после выбора бренда. Если правка в этих местах — проверь сценарий
отдельно (через `page.evaluate` по образцу скрипта) или попроси пользователя
проверить руками и опиши, что именно нажать.
