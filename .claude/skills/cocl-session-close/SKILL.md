# Закрытие сессии COCL

`PROJECT_SUMMARY.txt` — архив (форматы данных, поведение вкладок, история решений);
читается редко и по одному разделу, поэтому его **дописывают, а не переписывают**.
Правила проекта — в CLAUDE.md, карта кода — в PROJECT_MAP.md, текущее состояние —
в Handoff.md. Писать нужно по факту — по diff, а не по памяти о разговоре.

## Шаги

1. **Собери факты.**
   ```bash
   git log --oneline origin/main..HEAD      # коммиты сессии (или от начала сессии)
   git diff --stat origin/main
   git diff origin/main -- js | grep -E '^[+-]\s*(async )?function '
   ```
   Плюс то, что пользователь решил в разговоре (договорённости, отказ от идей,
   новые приоритеты) — это тоже факты, их нет в diff.

2. **Допиши в `PROJECT_SUMMARY.txt`** — только добавлением, разделы целиком не читай
   и не переписывай (читай только последний блок раздела 15 и конец раздела 19):
   - раздел 15 «Что сделано» — **добавь короткий блок новой сессии** (5–10 строк);
   - раздел 16 «Что осталось» — убери сделанное, добавь новое из разговора;
   - раздел 19 «Контекст последних сессий» — одна строка в список;
   - разделы 4–13 — правь точечно (Edit), только если изменился формат данных или
     поведение вкладки: новое поле, ключ localStorage; остальное не трогай;
   - удалённые функции и поля — пометь «УБРАНО» там, где они описаны.
   Правил кода и дерева файлов в резюме нет — они в CLAUDE.md и PROJECT_MAP.md.
   Номер сессии — следующий после последнего в разделе 19.

3. **Обнови `ROADMAP.txt`** — отложенные задачи (раздел 18 резюме — его копия).
   Если файла нет, создай его из раздела 18. Сделанное — убрать, новое
   отложенное — добавить.

4. **Проверь сам файл.** Файлы проекта в CRLF — правь через Edit точечно, не
   переписывай целиком через Write (переводы строк станут LF и diff будет на весь
   файл). Проверка: `file PROJECT_SUMMARY.txt` → «with CRLF line terminators».

5. **Обнови карту и передачу дел.**
   ```bash
   python3 .claude/skills/cocl-session-close/scripts/gen_project_map.py
   ```
   — пересоздаёт `PROJECT_MAP.md` (JS-модули и их функции со строками,
   блоки CSS, ключи localStorage). В `Handoff.md` перепиши разделы «Где
   остановились» и «Что делать дальше» — его читает следующая сессия первым.
   Затем обнови граф знаний: скилл `graphify` с аргументами `. --update`
   (перечитывает только изменённые файлы; код — бесплатно, токены — только на
   изменённые .md/.txt). `graphify-out/` в `.gitignore`, не коммитится. Если
   `graphify-out/graph.json` нет — пропустить шаг.

6. **Закоммить** документацию отдельным коммитом в ту же ветку:
   `docs: итоги сессии N — <2–4 слова о главном>`.

7. **Ответ пользователю** — 3–5 строк: что зафиксировано, что перенесено в
   «Осталось», и напоминание обновить инструкции проекта в claude.ai, если он
   хранит туда копию PROJECT_SUMMARY.txt (иначе следующая сессия получит старую).

## Чего не делать

- Не переписывать резюме «покрасивее» и не менять разделы, которых сессия не
  касалась — пользователь знает этот файл и ориентируется по нему.
- Не вносить планы, которые не обсуждались, как решённые.
- Не дублировать в резюме код — только поведение, имена функций/id/ключей.
